# 포트폴리오 UI 개편 — 2026-10-11

## 요청과 현재 상태

사용자가 포트폴리오 전체의 투박한 인상과 회색 배경을 개선하고, 실제 사람들의 의견과 한글 서체를 조사해 세련되고 절제된 화면으로 바꾸도록 요청했다. 기존 React 프로젝트를 수정했다. 코드·문서 작성 완료, 사용자 화면/기능 확인 대기다. 테스트·빌드·린트·서버 실행·브라우저 검증·배포는 수행하지 않았다.

## 조사에서 얻은 기준

아래 커뮤니티 의견은 개별 경험과 선호다. 특정 색이나 폰트가 AI 제작을 판별한다는 객관적 기준으로 다루지 않는다. 검색 중 반복되는 홍보성 글을 독립적인 여러 의견으로 합산하지 않았다.

- [Why is every AI website designed the same? — r/webdesign](https://www.reddit.com/r/webdesign/comments/1m2om61/why_is_every_ai_website_designed_the_same/): 같은 보라색, 카드, 그림자, 중앙 정렬 제목과 비슷한 SaaS 구성을 반복한다는 댓글이 있다. 디자인에 적용한 판단: 이미 있는 공장 자산과 개인의 경험을 크게 보여주고, 모든 내용을 똑같은 카드로 감싸지 않는다.
- [Is this design too minimalist? — r/webdesign](https://www.reddit.com/r/webdesign/comments/1sk5wn5/is_this_design_too_minimalist/): 작은 글씨, 옅은 회색 글자, 찾기 어려운 탐색 요소를 지적한 댓글이 있다. 디자인에 적용한 판단: 절제는 낮은 대비가 아니며, 본문과 조작을 충분히 읽을 수 있어야 한다.

| 서체 | 공식 설명과 활용 방향 | 이번 선택 |
| --- | --- | --- |

| [Wanted Sans](https://github.com/wanteddev/wanted-sans) | 기하학적 특징을 가진 산세리프, 제목·본문에 활용 | 좀 더 개성 있는 제목용 대안으로 조사. 이번에는 혼용하지 않음 |

서체가 흔하다는 이유만으로 교체하지 않았다. 제목 450–600 중심의 가변 굵기, 큰 제목의 자간, 본문 행간/읽기 폭을 조정했다. 기술 본문은 충분한 크기와 대비를 확보하는 방향으로 작성했다. 추가 폰트 다운로드·패키지 설치 없음. 실제 화면에서의 가독성 판단은 사용자 확인 대기다.

## 구현 방향과 파일

- `src/index.css`: 흰색 paper, 잉크색, 본문색, 보조색, 짙은 녹색 accent와 선 색상을 공통 변수로 정의. 포커스와 선택 색상 정리.
- `src/App.css`: 페이지 폭/바깥 여백/제목/공통 버튼 정리. 본문 선택자를 #content에 한정.
- `src/components/layout/`: 메뉴의 현재 페이지 표시, 작은 로고/연락 링크, 넓은 연락 영역과 하단 서명을 구성. nav/footer 전역 스타일을 사이트 범위로 한정.
- `src/pages/HomePage.*`: 짧은 개인 소개 문구, 대표 프로젝트 다음에 여백을 둔 프로필. 큰 이력 카드 대신 선과 정렬로 학력/경력/교육/기술/프로젝트를 구분.
- `src/components/truckworks/TruckWorksFeature.*`: 밝은 소개 글과 어두운 자체 공장 이미지의 비대칭 배치. 궤도 장식 제거, 본문/출처/개발 상태 가독성 조정. 실제 실행 화면이 아니라는 표기 유지.
- `src/pages/ProjectsPage.css`, `src/components/projects/ProjectListItem.css`: 이미지 비중 확대, 큰 제목, 기여 내용, 기술 목록, 구분선. 기존 이미지 전환/상세 링크 유지.
- `src/pages/AboutPage.*`: 소개 제목 추가, 데스크톱 지도 장식 축소. 760px 이하에서는 이야기 선택 목록과 상세 본문으로 배치하고 상세 선택 시 내용 위치로 이동. 기존 선택/닫기/프로젝트 링크 유지.
- `src/pages/EducationProjectPage.css`, `src/pages/InterviewProjectPage.css`, `src/components/projects/*.css`: 기존 보라색 계열 팔레트 정리, 문서형 상세 헤더/목차/선택 버튼/그래프/체험 화면 통일. 허용/차단 등 의미 있는 상태 색상은 구분 유지.
- `src/pages/TruckWorksProjectPage.css`, `src/components/truckworks/TruckWorksStory.css`: 밝은 설명 섹션, 읽기 크기 확대, 작은 화면의 단계 선택 및 공정 도식 배치. 기존 동작 설명/아키텍처/상세 펼치기 기능 유지.

## 사용자가 직접 확인할 절차

대상 폴더: `C:\Users\sp287\WebstormProjects\portfolio`

1. 필요 시 이 폴더에서 `npm run dev`를 실행해 홈, 프로젝트, 소개와 각 프로젝트 상세를 확인한다. 기존 개발 서버가 있다면 해당 주소를 사용한다.
2. 큰 화면과 390px/320px 폭에서 메뉴, 제목, 연락처, 프로젝트 이미지/본문이 화면 밖으로 잘리지 않는지 본다. 사이트 전체의 배경은 흰색이고 어두운 이미지는 프로젝트 내용에 집중되어야 한다.
3. 홈의 프로젝트 보기/이력서 다운로드/메일/학습 기록, 목록 이미지 전환, 상세 진입과 뒤로가기를 확인한다.
4. 소개의 여섯 항목을 선택하고 닫는다. 데스크톱에서는 지도, 모바일에서는 목록/상세가 보여야 하며 실제 읽는 흐름이 불편하지 않은지 확인한다.
5. 기존 교육/면접 페이지의 목차, 이미지 확대/닫기, 가드레일/인터뷰 선택·입력·그래프 상태를 확인한다. 현재 선택과 허용/차단 결과가 구별되어야 한다.
6. TruckWorks 설명 네 단계, 구조 세 관점, 설계 상세 펼치기와 내부 목차를 확인한다. 모바일의 공정 도식만 필요한 경우 가로로 움직이고 페이지 전체는 옆으로 밀리지 않아야 한다.
7. Tab으로 링크/버튼을 이동해 초점이 보이는지 확인하고, OS 모션 감소 설정에서도 탐색이 가능한지 확인한다.
8. 사용자가 직접 `npm run build`, `npm run lint`를 실행해 결과를 전달한다. 이번 기록은 이 명령들의 성공을 의미하지 않는다.

다음 단계는 실제 화면에 대한 사용자 피드백 반영이다. 새 디자인의 주관적 완성도, 반응형, 키보드 동작은 아직 사용자 검토 대기다.
